# 团队协作规范

> AI反诈骗检测系统 — 毕业设计团队开发规范

---

## 一、团队分工

| 角色 | 职责 | 技术栈 |
|------|------|--------|
| 后端开发 | 接口开发、数据库、安全、部署 | Spring Boot + MySQL + Redis |
| 前端开发 | 页面开发、数据可视化、交互 | Vue 3 + Element Plus + ECharts |
| AI算法 | 检测算法、模型训练、实验对比 | Python + PyTorch + Flask |

---

## 二、协作流程

### 接口先行原则
1. 后端先定接口文档（Swagger）
2. 前端根据文档用 Mock 数据开发
3. AI 算法提供 Flask 接口规格
4. 各自开发完成后再联调

### 联调节奏
- 每周至少一次集中联调
- 遇到接口问题及时在群里沟通
- 接口变更必须提前通知，不能私自改

---

## 三、Git 规范

### 提交信息格式
```
<type>: <description>
```

| type | 说明 |
|------|------|
| feat | 新功能/新页面/新算法 |
| fix | 修复 bug |
| docs | 文档更新 |
| style | 样式/格式调整 |
| refactor | 代码重构 |
| perf | 性能优化 |
| test | 测试相关 |
| chore | 构建/工具/依赖配置 |

### 示例
```
feat: 增加文本诈骗检测页面
fix: 修复登录token过期不跳转的问题
docs: 更新接口文档
```

### 分支策略
- `master` — 主分支，稳定版本，禁止直接提交
- `dev` — 开发分支，日常开发合入这里
- `feature/xxx` — 功能分支，开发完成提 PR 合入 dev
- `hotfix/xxx` — 紧急修复分支

## 四、代码规范

### 通用
- 代码必须有注释（关键逻辑、复杂算法）
- 命名见名知意，不用拼音
- 提交前自己测试过，不提交不能运行的代码

### Java 后端
- 遵循阿里巴巴 Java 开发规范
- 包名：`com.cucn.springboot.*`
- 类名大驼峰，方法名小驼峰

### 前端
- 使用 ESLint + Prettier
- Vue 3 Composition API（`<script setup>`）
- 组件名大驼峰，文件名与组件名一致

### Python
- 遵循 PEP 8
- 函数/类必须有 docstring
- 实验代码固定随机种子，保证可复现

---

## 五、文档规范

- 重要决策写进文档，不只靠口头沟通
- API 变更更新 Swagger 注释
- 数据库变更更新 SQL 脚本 + 数据库文档
- 实验结果保存数据和图表，不只有结论

---

## 六、进度管理

- 每周日晚上更新各自进度
- 遇到困难及时说，不拖到最后
- 延期提前一周预警，一起想办法
- 里程碑节点（中期检查、初稿、答辩）全体关注

---

## 七、沟通渠道

- 日常沟通：微信群
- 代码问题：Git Issue / 评论
- 文档协作：Markdown 文件，Git 管理
