### 关系说明

| 关系 | 类型 | 说明 |
|------|------|------|
| user → role | N:1 | 每个用户有一个角色 |
| role ↔ menu | N:N | 通过 sys_role_menu 关联，一个角色有多个菜单，一个菜单属于多个角色 |
| user → detection_record | 1:N | 一个用户有多条检测记录 |
| user → cert_record | 1:N | 一个用户有多条存证记录 |
| user → operation_log | 1:N | 一个用户有多条操作日志 |

## 三、表结构详解

### 3.1 用户表（sys_user）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | int | PK, AUTO_INCREMENT | 用户ID |
| username | varchar(50) | UNIQUE, NOT NULL | 用户名 |
| password | varchar(255) | NOT NULL | 密码（BCrypt哈希） |
| nickname | varchar(255) | | 昵称 |
| email | varchar(255) | | 邮箱 |
| phone | varchar(20) | | 手机号 |
| address | varchar(255) | | 地址 |
| avatar_url | varchar(255) | | 头像URL |
| role | varchar(50) | | 角色标识（ROLE_ADMIN / ROLE_WORKER） |
| roleid | int | FK → sys_role.id | 角色ID |
| sex | varchar(10) | | 性别 |
| description | varchar(255) | | 简介 |
| create_time | datetime | | 创建时间 |

> **注意**：password字段存储BCrypt哈希值，长度60字符。历史数据为MD5（32字符），首次登录自动迁移。

## 四、设计规范

### 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 表名 | 下划线 + 模块前缀 | `sys_user`, `detection_record` |
| 字段名 | 下划线 | `user_id`, `risk_score` |
| 主键 | `id` | id |
| 外键 | `关联表_id` | `user_id`, `role_id` |
| 索引前缀 | `idx_字段名` | `idx_user_id` |

### 字段类型选择原则

- **ID**：int + AUTO_INCREMENT（数据量不大的项目足够）
- **字符串**：varchar，长度按需分配
- **大文本**：text（JSON详情、长描述）
- **时间**：datetime（精度到秒）
- **金额/大小**：bigint（字节数等大数）
- **布尔**：用varchar或tinyint表示，不用boolean（移植性差）

### 索引设计原则

1. **主键索引**：每张表必须有主键
2. **外键字段**：所有关联字段加索引（user_id, role_id等）
3. **常用筛选字段**：type, status, risk_level等加索引
4. **排序字段**：create_time加索引（查询时按时间排序）
5. **索引不是越多越好**：写操作频繁的表少建索引

## 五、数据库初始化与升级

### 初始化（全新安装）

```bash
# 执行完整初始化脚本
mysql -u root -p < sql/anti_fraud.sql
```

### 从v1升级到v2

```bash
# 执行升级脚本（新增表、字段、索引）
mysql -u root -p anti_fraud < sql/upgrade_v2.sql
```

**升级内容：**
1. `detection_record` 表增加 `status` 字段
2. 新建 `sys_operation_log` 表
3. 新增查询索引
