# 反诈线索研判 Agent 模块需求规格说明

> 版本：0.2  
> 状态：题目、范围及评测方向已按指导老师意见确认；指标阈值由实际预实验确定  
> 依据：`agent-thesis-project-plan.md` 及现有比赛项目结构

## 1. 文档目的

本文定义本人毕设新增的 Agent 研判模块要解决的问题、功能范围和验收条件，供指导老师、团队成员和开发者确认。本文只描述“做什么”和“怎样验收”；数据库表结构、接口字段、工作流节点实现和部署细节留到需求确认后的技术设计阶段。

## 2. 模块定位

本模块面向疑似电信诈骗线索的初步研判。用户提交线索后，Agent 检查信息完整性，调用已有文本检测能力和反诈知识检索能力，生成带引用来源的研判草稿，供人工审核。

现有文本、语音、图像检测模型和证据存证/可视化系统属于团队已有能力。本模块调用约定的接口，不重新训练检测模型，也不承担存证和可视化子系统。

## 3. 用户与权限

| 用户角色 | 主要操作 |
|---|---|
| 研判人员 | 创建案件、提交线索、补充信息、查看 Agent 草稿和引用、提交审核意见 |
| 审核人员 | 查看待审结果、修改或退回草稿、确认审核结论 |
| 知识维护人员 | 添加或更新反诈知识材料及来源信息 |
| 系统维护人员 | 查看运行错误和服务状态，维护工具可用配置 |

具体角色是否合并，由现有系统权限模型和指导老师意见确定。

## 4. 功能需求

优先级说明：P0 为答辩演示闭环必需；P1 为时间允许时实现。

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-01 | P0 | 创建线索案件 | 用户可提交文本线索并获得案件编号；空内容或超出限制的输入会被拒绝并说明原因 |
| FR-02 | P0 | 检查信息完整性 | Agent 能指出预先定义的关键信息缺项，并请求用户补充；用户补充后可继续原案件流程 |
| FR-03 | P0 | 调用已有检测工具 | Agent 能通过受控工具接口调用现有文本检测服务，并保留原始检测结果及调用状态 |
| FR-04 | P0 | 检索反诈知识 | Agent 能从已整理的知识材料中检索相关内容；无匹配内容时明确返回未找到依据 |
| FR-05 | P0 | 生成结构化研判草稿 | 草稿包含线索摘要、已有检测结果、知识依据、待核实信息、建议核查步骤和不确定性说明 |
| FR-06 | P0 | 展示引用来源 | 每条知识引用都能定位到来源文档及段落；检测结果、引用事实和 Agent 汇总内容须有明确区分 |
| FR-07 | P0 | 人工审核与修改 | 审核人员可以确认、修改或退回草稿；系统保存审核状态和审核意见 |
| FR-08 | P0 | 暂停与恢复 | 信息补充或人工审核需要等待时，运行状态和必要上下文得以保存；收到后续输入后可继续处理 |
| FR-09 | P0 | 运行轨迹 | 用户或维护人员可查看案件运行状态、调用工具、调用结果状态、引用来源、耗时和错误信息 |
| FR-10 | P0 | 失败提示与降级 | 检测工具或检索工具不可用时，系统显示具体失败步骤；不得把失败伪装成低风险结果或虚构引用 |
| FR-11 | P1 | 知识材料维护 | 知识维护人员可新增、更新或停用材料，并保留来源、发布时间和版本信息 |
| FR-12 | P1 | 评测运行与报告 | 开发者可对固定测试集运行基线和 Agent 版本，导出指标与失败样例 |

## 5. 核心业务流程

### 5.1 信息完整、工具可用

1. 研判人员提交文本线索并创建案件。
2. Agent 检查输入，调用现有文本检测工具和反诈知识检索工具。
3. Agent 汇总检测结果与可定位的知识依据，生成结构化草稿。
4. 审核人员查看草稿和引用，确认或修改后完成案件。
5. 系统保存最终结果及本次运行的状态记录。

### 5.2 信息不足

1. Agent 发现必需信息缺项，列出需要补充的问题。
2. 案件进入等待状态，暂不生成确定性结论。
3. 用户补充信息后，系统恢复案件流程并继续必要的工具调用。

### 5.3 工具异常或无检索依据

1. 系统保留已成功的步骤及其来源。
2. 失败步骤标注工具、错误类别和是否可重试。
3. Agent 可以返回部分草稿和未完成项，但必须标注限制；不得填入虚构检测分数或引用。
4. 用户可选择重试、补充信息或结束当前运行。

## 6. 输出要求

每次 Agent 运行至少返回以下信息：

- 案件编号、运行编号和当前状态。
- 用户提交内容的简要结构化摘要。
- 现有检测工具返回的原始风险结果及调用状态。
- 检索到的知识材料来源和段落定位；无结果时明确标注。
- 研判草稿、待核实信息、建议核查步骤和不确定性说明。
- 人工审核状态及审核意见（审核后）。
- 工具调用错误和未完成步骤（发生异常时）。

系统不向用户展示模型隐藏思维链。运行轨迹记录可观察的状态变化、工具名称、参数摘要、结果状态和耗时。

## 7. 非功能需求

### 7.1 安全与隐私

- MCP 工具采用白名单；本期仅允许调用检测和知识检索等只读能力。
- 工具输入必须经过结构校验；用户内容和检索文档视为不可信输入，不能修改工具权限。
- 沿用现有登录和权限边界；案件和运行记录不得跨用户越权读取。
- 评测和演示优先使用合成或脱敏数据；日志不保存不必要的敏感原文。
- Agent 只生成辅助研判材料，不自动执行外部处置。

### 7.2 可恢复性

- Agent 运行须有明确状态和可查询的运行编号。
- 对超时、限流、无效响应等预期故障提供可区分的错误状态。
- 人工暂停、补充信息和审核后续办均须覆盖测试。

### 7.3 可追溯性

- 每条知识依据能定位到当前知识库中的具体文档和段落。
- 每个检测结果能关联到对应工具调用状态。
- 评测报告记录数据版本、模型/提示配置、执行时间和指标口径。

### 7.4 性能与容量

- 响应时延、并发量、输入长度和工具超时阈值在最小闭环完成后，通过基线测试确定并记录。
- 对外部模型或服务的耗时应单独统计，避免把第三方服务延迟误判为本地 Agent 服务性能。

## 8. 验收测试场景

| 场景 | 输入/条件 | 预期结果 |
|---|---|---|
| AT-01 正常线索 | 文本线索完整，检测与知识检索服务可用 | 生成结构化草稿，检测结果和引用可回查 |
| AT-02 缺少信息 | 输入缺少预定义关键字段 | 请求补充并暂停；补充后能继续同一案件 |
| AT-03 知识无匹配 | 检测服务正常，知识库没有相关条目 | 明确表示没有检索到依据，不生成伪引用 |
| AT-04 检测服务超时 | 检测工具在限定时间内无响应 | 标记检测调用失败，保留其他成功信息，不输出伪造分数 |
| AT-05 非法工具参数 | Agent 生成不符合工具 schema 的参数 | 工具层拒绝调用并记录错误 |
| AT-06 人工退回 | 审核人员退回并给出修改意见 | 案件进入待修改状态，后续运行能关联原审核意见 |
| AT-07 提示注入样例 | 线索文本要求忽略规则或调用未授权工具 | Agent 仍只能调用白名单工具，不执行未授权操作 |
| AT-08 权限边界 | 未授权用户读取其他用户案件或运行记录 | 请求被拒绝并留下安全审计结果 |

## 9. 评测要求

建立约 100–200 条人工核验的离线场景，覆盖正常、模糊、缺项、知识无匹配、工具异常和提示注入等类别。评测集不用于重新训练团队检测模型。

对比“现有检测接口”“单轮 LLM 生成”和“Agent 工作流”三种结果，至少报告：

- 任务完成率和关键信息抽取正确率。
- 工具选择准确率和工具参数有效率。
- 引用可定位率及引用内容支持准确率。
- 失败后的正确降级率和越权工具拦截情况。
- 响应时延及模型调用成本估算。

具体达标阈值由预实验和指导老师共同确认；论文报告实际测得结果，不预填或推测实验数据。

## 10. 明确不属于本模块的需求

- 诈骗文本识别模型训练、模型结构改进和分类指标优化。
- 区块链证据上链、证据管理、证据可视化和独立仪表盘。
- 自动报警、冻结账户、联系用户或其他具有外部副作用的操作。
- 语音/图像模型重做、多 Agent 协作、任意网页浏览和自动代码执行。

## 11. 指导老师确认结论

以下结论根据学生转述的线下沟通记录整理，后续如老师补充要求，以正式要求为准：

1. 题目无需调整，暂定题目保持为“面向电信诈骗线索研判的可控智能体工作流系统设计与实现”。
2. 可在说明个人贡献及复用来源的前提下复用宿舍比赛项目代码和数据；具体数据使用仍遵守团队授权与脱敏要求。
3. 本人负责 Agent 工作流、MCP 工具接入、RAG 引用、人工复核和评测；不将室友负责的检测模型、存证及可视化写成本人新增成果。
4. MVP 以文本线索为主；已有语音、图像能力不作为本期必做范围。
5. 学院未规定评测指标或阈值；应实现测试与评测脚本，记录优化前后实测数据、指标口径和失败样例，不得预填结果。
6. 学校未限定运行环境、数据库或部署方式；沿用现有项目环境并以可复现部署为目标。

## 12. 进入详细设计的依据与遗留事项

题目、职责边界、MVP 输入和评测方向已经确认，进入架构与接口详细设计。仍需在实施中落实但不阻塞设计的事项：

- 与团队确认具体可复用接口、数据集使用授权和论文中的贡献说明。
- 选定并记录知识材料来源、许可信息、版本及脱敏规则。
- 通过预实验确定评测集最终规模、模型/检索配置和指标阈值；论文只报告实际跑分。
- 依据现有系统权限及部署配置，完成 Agent 内部服务鉴权和密钥管理。
