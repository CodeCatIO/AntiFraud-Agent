# 部署文档

> **项目**：AI反诈骗检测系统
> **部署方式**：Docker Compose 一键部署
> **环境要求**：Docker 20.10+ + Docker Compose v2

---

## 一、部署架构

```
                      ┌─────────────┐
                      │    Nginx    │  :80
                      │ (反向代理)   │
                      └──────┬──────┘
                             │
              ┌──────────────┴──────────────┐
              ▼                             ▼
      ┌──────────────┐              ┌──────────────┐
      │   Frontend   │              │   Backend    │
      │  Vue dist    │              │  Java 17     │
      │  静态资源     │              │  :9090       │
      └──────────────┘              └───┬──────┬───┘
                                        │      │
                   内网 HTTP + Token     │      │
                     (不映射宿主端口)      ▼      ▼
                              ┌──────────────┐  ┌──────────────┐
                              │ Agent Service│  │  AI Service  │
                              │ Python/LangGraph│ │ Python 3.10 │
                              │   :8001      │  │   :5000      │
                              └───┬──────┬───┘  └──────────────┘
                                  │      │
              MCP(同机 stdio/HTTP)  │      │ 事件回写 /internal/agent/v1/runs
                                  ▼      └──────────────► Backend
                        ┌──────────────────┐
                        │ SQLite checkpoint│ 卷 agent-checkpoint-data
                        └──────────────────┘

      Backend ──► MySQL 8.0   /   Redis 7.x
```

## 三、快速开始（3步启动）

### 第1步：准备环境变量

```bash
# 复制环境变量模板
cp .env.template .env

# 编辑 .env 文件，修改密码等敏感配置
# 至少修改 DB_PASSWORD、JWT_SECRET、AGENT_SERVICE_TOKEN
# AGENT_SERVICE_TOKEN 必须非空（compose 使用 :? 强制校验，缺失会直接启动失败）
```

### 第2步：构建并启动

```bash
# 构建镜像并启动全部服务（后台运行）
docker compose up -d --build
```

### 第3步：验证

```bash
# 查看服务状态
docker compose ps

# 查看后端日志
docker compose logs -f backend

# 健康检查
curl http://localhost:9090/health
```

**启动成功后访问：**
- 前端页面：http://localhost
- 后端API：http://localhost/api/
- Swagger文档：http://localhost/swagger-ui.html
- 健康检查：http://localhost/health

## 五、前端部署

前端需要先构建出 dist 目录，然后挂载到 Nginx：

### 构建前端

```bash
cd frontend
npm install
npm run build
# 构建产物在 frontend/dist/ 目录
```

### 挂载到 Docker

修改 `docker-compose.yml` 的 nginx 部分：

```yaml
  nginx:
    # ...
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
      - file-data:/app/files
      - ./frontend/dist:/usr/share/nginx/html:ro  # 加上这一行
```

然后重启 nginx：
```bash
docker compose restart nginx
```

## 八、常见问题

### Q1: 首次启动后端连不上数据库

**A**: 数据库初始化需要时间。`docker-compose.yml` 中已经配置了健康检查依赖，后端会等MySQL就绪后再启动。如果还是有问题，查看日志：
```bash
docker compose logs mysql
docker compose logs backend
```

### Q2: 前端页面刷新后404

**A**: Vue Router history模式需要Nginx配置try_files。当前nginx.conf已配置。如果还是有问题，检查：
```bash
docker compose exec nginx cat /etc/nginx/nginx.conf
```

### Q3: 上传文件大小限制

**A**: Nginx默认限制100M，后端限制100M。修改：
- `nginx.conf` 中的 `client_max_body_size`
- `application.yml` 中的 `spring.servlet.multipart.max-file-size`

### Q4: Agent 创建后一直停在 QUEUED / RUNNING

**A**: 按顺序排查：
```bash
docker compose logs --tail=100 agent-service
docker compose logs --tail=100 backend
docker compose exec agent-service env | findstr AGENT_SERVICE_TOKEN
```
常见原因：`AGENT_SERVICE_TOKEN` 两端不一致（401）、`AGENT_SERVICE_URL` 配错、
`agent-service` 不健康导致后端未启动、Agent 无法回写 `BACKEND_EVENT_URL`。
事件回写失败时 Agent 会把该 Run 标记为 `CALLBACK_FAILED`。

### Q5: 报错 `Table 'anti_fraud.agent_run' doesn't exist`

**A**: 已有 MySQL 数据卷不会自动执行新增迁移，按“十一、Agent 服务与数据迁移”手工执行 V001/V002。

### Q6: 审核提交提示 non-editable fields

**A**: 审核只允许修改 `summary`、`missingInformation`、`suggestedChecks`、`uncertaintyNotes`；
检测分数、引用等字段不可改。后端与 Agent 都会在写入检查点前拒绝非法字段，非法请求不会污染该 Run。

### Q7: 怎么查看服务是否健康

**A**: 访问健康检查接口：
```bash
curl http://localhost/health
# 返回 status: ok/degraded/down
# components: { backend, database, redis, aiService }
```

## 十一、Agent 服务与数据迁移

### 11.1 启动与健康检查

```bash
docker compose up -d --build
docker compose ps                     # backend / agent-service 均应为 healthy
docker compose logs -f agent-service  # 应看到 Uvicorn 监听 8001
```

- `agent-service` 只在 Compose 内网暴露 `8001`，**不要加 ports 映射**，浏览器只能访问后端。
- backend 依赖 `agent-service: condition: service_healthy`，Agent 不健康时后端不会启动。
- Agent 健康检查地址：容器内 `http://localhost:8001/health`；后端存活检查：`http://localhost:9090/health/liveness`。

### 11.2 数据库迁移

Agent 相关表由两个迁移脚本创建：

| 脚本 | 内容 |
|------|------|
| `sql/migrations/V001__agent_core.sql` | `agent_case`、`agent_run`、`agent_event` |
| `sql/migrations/V002__agent_human_review.sql` | `agent_review`、审核字段与索引 |

- **全新数据卷**：`docker-compose.yml` 已把 V001/V002 挂载到 MySQL 初始化目录，首次启动自动执行。
- **已有数据卷**：初始化脚本不会重跑，需要手工执行（脚本使用 `CREATE TABLE IF NOT EXISTS`，可重复执行）：

Bash:
```bash
docker compose exec -T mysql mysql -uroot -p"$DB_PASSWORD" anti_fraud < sql/migrations/V001__agent_core.sql
docker compose exec -T mysql mysql -uroot -p"$DB_PASSWORD" anti_fraud < sql/migrations/V002__agent_human_review.sql
```

PowerShell:
```powershell
Get-Content .\sql\migrations\V001__agent_core.sql -Raw | docker compose exec -T mysql mysql -uroot -p"$env:DB_PASSWORD" anti_fraud
Get-Content .\sql\migrations\V002__agent_human_review.sql -Raw | docker compose exec -T mysql mysql -uroot -p"$env:DB_PASSWORD" anti_fraud
```

验证：
```bash
docker compose exec mysql mysql -uroot -p"$DB_PASSWORD" anti_fraud -e "SHOW TABLES LIKE 'agent_%';"
```

### 11.3 回滚

- **表结构**：迁移只做新增，没有自动回滚脚本。需要回退时先备份，再按依赖倒序删表：
  `agent_review` → `agent_event` → `agent_run` → `agent_case`。删除会丢失 Agent 业务数据。
- **知识索引**：可切换到上一版本，无需删数据：
  ```bash
  docker compose exec agent-service python scripts/build_knowledge_index.py --rollback
  ```
- **代码回滚**：重新部署上一版本镜像。旧版本能否读取新版本写出的 SQLite 检查点未验证，降级前先备份检查点卷。

### 11.4 检查点备份与恢复

检查点保存在命名卷 `agent-checkpoint-data`（`/data/agent-checkpoints.sqlite`）。

```bash
# 备份（建议先暂停 Agent，保证 SQLite 文件一致）
docker compose stop agent-service
docker run --rm -v anti-fraud_agent-checkpoint-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/agent-checkpoints.tar.gz -C /data .
docker compose start agent-service

# 恢复
docker compose stop agent-service
docker run --rm -v anti-fraud_agent-checkpoint-data:/data -v "$PWD":/backup alpine \
  sh -c "rm -f /data/* && tar xzf /backup/agent-checkpoints.tar.gz -C /data"
docker compose start agent-service
```

### 11.5 密钥配置与轮换

```bash
# 生成随机密钥（任选其一）
openssl rand -hex 32
python -c "import secrets; print(secrets.token_hex(32))"
```

把同一个值同时写入 `.env` 的 `AGENT_SERVICE_TOKEN`，然后：
```bash
docker compose up -d backend agent-service
```
密钥不一致时，后端派发返回 401、Agent 事件回写也会被后端 401 拒绝。

### 11.6 Agent 端到端验收清单

1. 登录普通用户 → 新建案例 → Run 依次经过 `QUEUED → RUNNING → WAITING_FOR_REVIEW`。
2. 信息不足时进入 `WAITING_FOR_INFO`，补充一轮后进入审核；补充内容会重新进入检测。
3. 审核通过 → `COMPLETED`；退回 → `RETURNED`；修改仅允许白名单字段。
4. 同一 `eventSeq` 重放不会重复推进状态；旧事件不会覆盖新状态。
5. 重启 `agent-service` 后，处于 `WAITING_FOR_REVIEW` 的 Run 仍可继续审核。
6. 浏览器无法直连 `8001`；`/internal/agent/v1/runs` 缺少或错误 Token 返回 401。
